## 2. Назначение и цели

### 2.1. Назначение
Приложение «Личный дневник» — персональное пространство для свободного выражения мыслей, чувств и переживаний. Интеллектуальная составляющая: анализ записей и предложение связанных материалов. Публикация записей не предусмотрена — приложение полностью приватно.

### 2.2. Цели
- Качественный дневник для Windows без достойных аналогов на рынке
- Приватность: записи не публикуются
- Работа офлайн для неавторизованных пользователей
- Синхронизация с сервером для авторизованных
- Интеллектуальные рекомендации на основе анализа текста
- Инструменты рисования для визуализации мыслей

### 2.3. Платформы

|-----------|-------------|--------|
| Windows | 1 (приоритет) | Разработка |

## 4. Архитектура системы

### 4.1. Общая схема

```
┌─────────────────────────────────┐
│   Клиент (Tauri 2, Windows)     │
│   React + TypeScript            │
│   ┌─────────┐  ┌─────────────┐  │
│   │ SQLite  │  │  Rust Core  │  │
│   │(локал.) │  │  (backend)  │  │
│   └─────────┘  └─────────────┘  │
└───────────────┬─────────────────┘
                │ HTTPS / WebSocket
                │ (синхронизация)
┌───────────────▼─────────────────┐
│   Сервер (Docker)               │
│   Axum (Rust) — REST API        │
│   PostgreSQL                    │
│   Админ-панель localhost:1111   │
└─────────────────────────────────┘
```

### 4.2. Режимы работы

| Режим | Хранение | Синхронизация | Функции |
|-------|----------|---------------|---------|
| Неавторизован | SQLite локально | Нет | Базовый дневник, метка «Неавторизован» |
| Авторизован | SQLite + PostgreSQL | Да, автоматически | Полный функционал |

**Неавторизованный пользователь:** данные хранятся только локально в SQLite. В интерфейсе постоянно отображается метка «Неавторизован». Записи не синхронизируются с сервером и не видны администратору.

**Авторизованный пользователь:** все данные (записи, медиафайлы, настройки) отправляются на сервер и привязываются к аккаунту по User ID. Локальный SQLite работает как кэш для офлайн-доступа, синхронизация происходит при подключении к сети.

### 4.3. Идентификация пользователей

- Каждый авторизованный пользователь получает уникальный `user_id` (UUID v4)
- В админ-панели пользователи отображаются с их `user_id`
- Авторизация: email + пароль, опционально Windows Hello
- Гостевой режим не требует регистрации

## 7. Серверная часть и API

### 7.1. REST API (Axum)

Базовый URL: `https://api.dnevchik.local` (или настраиваемый)

**Аутентификация:**
```
POST /auth/register     — регистрация
POST /auth/login        — вход, возвращает JWT
POST /auth/logout       — выход
POST /auth/refresh      — обновление токена
```

**Записи:**
```
GET    /entries              — список записей пользователя
POST   /entries              — создать запись
GET    /entries/:id          — получить запись
PUT    /entries/:id          — обновить запись
DELETE /entries/:id          — пометить как архивное
GET    /entries/search?q=    — полнотекстовый поиск
```

**Медиафайлы:**
```
POST   /media/upload         — загрузить файл
GET    /media/:id            — получить файл
DELETE /media/:id            — удалить файл
```

**Синхронизация:**
```
POST   /sync                 — синхронизация пакета изменений (delta sync)
GET    /sync/status          — статус последней синхронизации
```

**Пользователь:**
```
GET    /user/profile         — профиль
PUT    /user/profile         — обновить профиль
GET    /user/stats           — статистика
```

### 7.2. Схема базы данных (PostgreSQL)

```sql
-- Пользователи
users (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  email       TEXT UNIQUE NOT NULL,
  password    TEXT NOT NULL,              -- bcrypt hash
  created_at  TIMESTAMPTZ DEFAULT now(),
  last_seen   TIMESTAMPTZ
)

-- Записи
entries (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID REFERENCES users(id),
  title       TEXT,
  content     TEXT,                       -- Markdown
  mood        SMALLINT CHECK (mood BETWEEN 0 AND 10),
  location    JSONB,                      -- {lat, lng, name}
  tags        TEXT[],
  is_archived BOOLEAN DEFAULT false,
  created_at  TIMESTAMPTZ DEFAULT now(),
  updated_at  TIMESTAMPTZ DEFAULT now()
)

-- Медиафайлы
media (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  entry_id    UUID REFERENCES entries(id),
  user_id     UUID REFERENCES users(id),
  type        TEXT,                       -- image, audio, video, file
  filename    TEXT,
  path        TEXT,
  size_bytes  BIGINT,
  created_at  TIMESTAMPTZ DEFAULT now()
)

-- Категории
categories (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id     UUID REFERENCES users(id),
  parent_id   UUID REFERENCES categories(id),
  name        TEXT NOT NULL
)

-- Полнотекстовый поиск
CREATE INDEX entries_fts ON entries USING GIN(to_tsvector('russian', content));
```

### 7.3. Синхронизация

- Delta sync: клиент отправляет только изменения с timestamp последней синхронизации
- Конфликты: побеждает запись с более поздним `updated_at`
- Офлайн: изменения накапливаются в локальном SQLite, применяются при восстановлении соединения

### 9.5. Соответствие GDPR / приватность

- При авторизации: пользовательское соглашение с прокруткой всего текста + краткая сводка собираемых данных
- Пользователь может запросить экспорт всех своих данных
- Удаление аккаунта: полная очистка данных на сервере в течение 30 дней

## 13. Ограничения и допущения

### 13.1. Ограничения
- Первоочередная разработка для Windows
- Облачная синхронизация только для авторизованных пользователей
- Администратор видит записи пользователей (условие по заданию)
- Шрифт Tinkoff Sans не используется — заменён Inter + Golos Text (лицензионные)

### 13.2. Допущения
- Сервер разворачивается локально через Docker
- Адрес сервера настраивается в клиентском приложении
- Интернет-соединение требуется только для синхронизации и карт
